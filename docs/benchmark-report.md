# AI 智能导购商城量化测试报告

## 1. 测试结论

本报告基于 2026-08-21 的固定数据集和独立数据库 `ai_mall_benchmark`。生产/展示数据库 `ai_mall` 未参与重建或清理。原始数据见 [benchmark-results.json](benchmark-results.json)。

原简历中的 30%、45%、60%、90%、50% 没有可信历史基线，不能继续作为既定成果使用。实测可以支持的核心结论是：混合 RAG 相对纯向量的 nDCG@5 提升 9.36%；2000 次并发鉴权请求无串号；26 项价格/库存事实无错误；Agent 完成率 100%，延迟中位数 12.219 秒。

## 3. 计算口径与通过标准

- `Precision@5 = Top 5 中相关结果数 / 5`。
- `Recall@5 = Top 5 中相关结果数 / 预期相关结果总数`。
- `MRR@5 = 首个相关结果排名的倒数`，前 5 无相关结果时为 0。
- `nDCG@5 = DCG@5 / 理想 DCG@5`，用于衡量相关结果的位置质量。
- nDCG 相对提升：`(当前值 - 基线值) / 基线值 x 100%`；绝对提升按百分点报告。
- P95 取排序后第 95 百分位的观测延迟。

| 测试项 | 通过标准 | 结果 |
| --- | --- | --- |
| 搜索 | 当前 nDCG@5 高于名称基线，记录所有零结果 | 通过，但仍有 14/40 条零命中 |
| JWT | 访问矩阵全通过；串号、越权、请求错误为 0 | 通过 |
| RAG | 混合检索 nDCG@5 不低于纯向量；跨商品失败可追踪 | 通过，2/40 条未命中 |
| Tool | 7 个配置与 Schema 有效；价格库存与 DB 一致 | 通过 |
| 在线问答 | 场景成功且事实有依据 | 18/18 通过 |
| Agent | 场景完成；价格库存事实错误为 0；审计完整率单列 | 10/10 完成，9/10 有推荐且审计完整 |
| 前端 | 构建成功，3 条核心 E2E 流程通过 | 通过 |

## 4. 商品搜索

基线仅执行“商品名称包含查询词”；当前方案执行真实 `ProductMapper` 查询，关键词覆盖名称、卖点、详情、参数、分类和品牌，并支持分类、品牌、最低价、最高价组合条件。

| 指标 | 名称基线 | 当前方案 |
| --- | ---: | ---: |
| Precision@5 | 0.02 | 0.15 |
| Recall@5 | 0.08 | 0.63 |
| MRR@5 | 0.08 | 0.65 |
| nDCG@5 | 0.08 | 0.63 |
| 零结果率 | 92.5% | 35.0% |
| 平均响应时间 | 4.59 ms | 2.57 ms |

nDCG@5 绝对提升 55.57 个百分点。相对值为 740.88%，但名称基线过弱，不适合写进简历。当前方案仍未覆盖同义词和多词语义，14 个失败查询包括“轻薄办公”“三分钟咖啡”“卧室静音净化”“高性能创作”等，应作为后续搜索优化集保留。

## 5. JWT 与 ThreadLocal

公开接口、无 Token、伪造 Token、过期 Token、用户访问管理员接口、管理员正常访问共 6 个场景全部通过。20 个线程各执行 100 次管理员/用户交错请求，共 2000 次：身份串号 0、请求错误 0、越权放行 0。

本次同时补充 JWT 过期校验回归测试。由于没有改造前的真实错误日志，不使用“鉴权错误率降低 90%”，建议描述为“完成 2000 次并发身份隔离测试，未发现身份串号或越权放行”。

## 6. RAG 检索与问答

| 指标 | 纯向量 | 混合检索 |
| --- | ---: | ---: |
| Precision@5 | 0.18 | 0.19 |
| Recall@5 | 0.88 | 0.95 |
| MRR@5 | 0.76 | 0.83 |
| nDCG@5 | 0.79 | 0.86 |
| 零结果率 | 0% | 0% |

混合检索 nDCG@5 相对提升 9.36%，不是 45%。失败的 2 个问题为“降噪耳机续航和降噪深度是多少”和“轻薄本适不适合移动办公”，说明本地降级向量对组合语义仍有不足。

在线问答 18/18 成功且通过依据检查；延迟平均 1.040 秒、中位数 1.206 秒、P95 1.593 秒。测试覆盖 12 个商品知识问题、3 个实时价格库存问题、3 个未知/跨商品问题，并检查多轮上下文。在线结果与离线 Embedding 模式分开统计。

## 7. Function Calling 与 Agent

启用工具为 `searchProducts`、`getProductDetail`、`getUserProfile`、`getSimilarProducts`、`getOrderStatus`、`getAfterSaleRule`、`submitRecommendation`。7 个工具定义都能归一化为合法对象型 JSON Schema，价格/库存工具结果与数据库逐字段一致。

`getUserProfile` 现在从用户订单、订单商品和收藏表派生画像，返回订单数量、收藏数量、购买过的商品、偏好品类和偏好品牌；没有历史行为时返回空画像。工具真实性仍只限定为价格、库存、订单、售后和这些数据库派生字段。

| Agent 指标 | 结果 |
| --- | ---: |
| 场景完成 | 10/10 |
| 产生有效推荐 | 9/10 |
| 审计完整 | 9/10 |
| 已核对价格/库存事实 | 26 |
| 事实错误率 | 0%（0/26） |
| 平均记录工具步骤 | 10.5 |
| 延迟中位数 / P95 | 12.219 s / 17.073 s |

没有旧固定流程的可信延迟样本，因此删除“等待时间减少 60%”。0% 事实错误只代表本轮 26 个被核对断言，不代表所有未来输入绝不出错。

## 8. 前端端到端验证

Playwright 在独立测试库上验证了三条流程：

1. 用户登录、关键词筛选、商品图片、详情 AI 区、购物车、地址、提交订单、余额支付、订单状态、钱包、个人资料和 AI 导购入口。
2. 管理员登录及商品、模型 Prompt、知识库、Agent、运营分析入口的一一对应。
3. 390x844 移动端登录、导航和商品页可达性。

结果为 3/3 通过，`npm run build` 通过。开发效率无法从代码仓库逆向量化，因此不保留“页面开发效率提升 50%”。

| 原描述 | 代码事实 | 实测结果 | 建议改写 |

## 10. 复现方式

测试数据在 `backend/src/test/resources/benchmark-cases.json`。`RUN_BENCHMARK=true` 才允许重建固定名称的测试库；`RUN_AI_BENCHMARK=true` 才执行在线 AI 测试。前端代理可通过 `VITE_API_TARGET` 指向独立后端。在线测试按约每 6.1 秒一次请求节流，避免超过每分钟 10 次。

运行命令见项目 README。报告生成时间和原始失败列表以 JSON 为准。
